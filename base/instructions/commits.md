# Commits and pull requests

- One logical change per commit. The subject line says what changes, in the imperative, in 72 characters or fewer.
- Work on a branch and open a pull request; do not commit to the default branch.
- Never commit a secret (a token, a password, a private key). Read it from the environment instead.
- Run the project's tests before you commit, and say in the pull request how the change was checked.
- Commit, push and open a pull request only when the person you work for asks you to.
- Reference the issue a change belongs to in the pull request, not in every commit.
